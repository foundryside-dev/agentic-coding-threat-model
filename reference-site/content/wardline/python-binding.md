The Python binding (Part II-A) provides the Python-specific enforcement reference for the Wardline framework. Section A.3 (interface contract) is normative; all other sections are non-normative.

## Design history

The wardline concept emerged through three iterations of structured adversarial deliberation using prompted AI agent teams. Iteration 1 concluded that changing Python's permissive defaults at the language level was not viable. Iteration 2 independently generated the concept of a standalone AST-based analysis layer that extends Python's existing annotation machinery — the creative pivot from "change the language" to "analyse the language" was generated by the agent team. Iteration 3 used seven specialist agent perspectives to refine the design, replacing binary taint tracking with the two-dimensional model tracking trust classification and validation status as orthogonal dimensions.

**Feasibility finding.** The deployed predecessor validates the approach: automated detection of common agentic code failure modes is technically feasible for Python, compatible with existing development workflows, and buildable at modest cost.

**Posture: reference implementation, not product.** The Python enforcement regime is a composition of existing ecosystem tools — ruff for syntactic pattern detection, mypy for type-layer tier diagnostics — and a reference implementation covering tier-aware taint-flow tracking, structural verification, and governance orchestration. The specification is designed so that any tool author can independently implement a compatible Wardline-Core scanner, Wardline-Type plugin, or Wardline-Governance orchestrator.

## Python language evaluation

| Criterion | Assessment | Detail |
|-----------|------------|--------|
| **Annotation expressiveness** | Strong | Decorators can express all 17 annotation groups. Metadata-only, visible to `ast.parse()` without execution. |
| **Parse tree access** | Strong | The `ast` standard library module ships with every CPython install. Zero external dependencies. |
| **Type system metadata** | Moderate | `typing.Annotated` (Python 3.9+) enables field-level tier marking. However, type hints are optional and not enforced at runtime. |
| **Structural typing** | Moderate | `typing.Protocol` (Python 3.8+) enables structural subtyping. `@runtime_checkable` Protocols support `isinstance()` checks. |
| **Runtime object model** | Strong | Descriptors (`__get__`/`__set__`/`__set_name__`), `__init_subclass__`, and metaclasses provide rich runtime structural enforcement. |
| **Serialisation boundary control** | Weak | `json.loads()` returns `dict` regardless of what was serialised. Static analysis cannot cross serialisation boundaries. |
| **Tooling ecosystem** | Strong | mypy, pyright, ruff, bandit, and extensive AST tooling. SARIF standard interchange format. |

### Where Python falls short

- **No linear types** — Python cannot prevent aliasing of validated data. A `ValidatedRecord` can be assigned to multiple variables, passed to functions that mutate it, or stored in containers that mix tiers.
- **No compile-time enforcement** — type checking is optional. Nothing prevents a developer or agent from ignoring type annotations entirely.
- **No ownership model** — Python cannot prevent lower-tier data from being aliased as Tier 1 without active enforcement mechanisms (descriptors, runtime checks).

These limitations define the ceiling of assurance achievable through this language binding. **Minimum Python version: 3.12+.**

### Ecosystem tool coverage

| Conformance Profile | Candidate Tool | Implementation Path | Fit |
|---|---|---|---|
| Advisory fast path (non-conformant) | ruff | Custom rule plugin — syntactic pattern matching for PY-WL-001 through PY-WL-005 | Strong — ruff's per-file AST rule architecture matches pattern detection directly. Advisory only: no manifest, no tier-graded SARIF |
| Wardline-Core (authoritative) | Bespoke scanner | Two-pass AST analysis with taint tracking, manifest consumption, SARIF output | Required — no existing tool provides tier-aware severity grading |
| Wardline-Type | mypy plugin | Plugin using mypy's type analysis hooks to understand `Annotated` tier metadata | Strong — mypy's plugin API supports custom type metadata |
| Wardline-Type (baseline) | pyright (no plugin) | Standard `typing.Protocol` and `typing.Annotated` mechanisms | Moderate — structural conformance but no tier-flow analysis |
| Wardline-Governance | Bespoke CLI | Manifest validation, fingerprint baseline, SARIF aggregation, control-law reporting | Required — governance is wardline-specific |

## Interface contract (Wardline-Core)

*This section is normative.*

Any tool that implements Wardline-Core rules for the Python regime MUST satisfy the following:

1. **Manifest consumption.** The tool MUST consume `wardline.yaml` and overlays and validate against the framework's JSON Schemas before producing findings.
2. **Decorator discovery.** The tool MUST discover wardline decorator syntax from the target codebase's AST. The tool SHALL NOT rely on runtime introspection as the primary discovery mechanism.
3. **Schema default recognition.** The tool MUST recognise `schema_default()` as a PY-WL-001 suppression marker. Calls wrapped in `schema_default()` where the default matches the overlay's approved default are governed by the overlay declaration.
4. **SARIF output.** SARIF v2.1.0 with wardline-specific property bags. Required keys: `wardline.rule`, `wardline.taintState`, `wardline.enclosingTier`, `wardline.severity`, `wardline.exceptionability`, `wardline.analysisLevel`, `wardline.excepted`, `wardline.annotationGroups`.
5. **Rule declaration.** The tool MUST declare which rules it implements and maintain golden corpus specimens.
6. **Verification mode.** The tool SHOULD support `--verification-mode` for deterministic byte-identical output.

### Rule mapping

The Python binding splits WL-001 into two rules because Python has two distinct access-with-fallback idioms:

| Python Rule | Framework Rule | Pattern |
|---|---|---|
| PY-WL-001 | WL-001 (split) | Dict key access with fallback default (`.get()`, `.setdefault()`, `collections.defaultdict`) |
| PY-WL-002 | WL-001 (split) | Attribute access with fallback default (`getattr()` with default, `hasattr()` guards) |
| PY-WL-003 | WL-002 | Existence-checking as structural gate (`if key in dict`, `hasattr()` guards) |
| PY-WL-004 | WL-003 | Broad exception handlers (`except Exception`, bare `except`) |
| PY-WL-005 | WL-004 | Catching exceptions silently (`except: pass`, bare `except` with no re-raise) |
| PY-WL-006 | WL-005 | Audit-critical writes inside broad exception handlers |
| PY-WL-007 | WL-006 | Runtime type-checking internal data (tier-dependent — suppressed at Tier 4) |
| PY-WL-008 | WL-007 | Validation boundary with no rejection path (structural verification) |
| PY-WL-009 | WL-008 | Semantic validation without prior shape validation (validation ordering) |

PY-WL-001 through PY-WL-005 are syntactic patterns detectable by per-file AST analysis (ruff advisory path). PY-WL-006 through PY-WL-009 require semantic context and are implemented by the reference scanner.

**Severity matrix.** The Python binding extends the parent specification's 8x8 matrix to 9x8 by splitting WL-001. No cell values are changed. The total is 26 UNCONDITIONAL cells.

## Annotation vocabulary

The 17 annotation groups are expressed as Python decorators. Decorators set `_wardline_*` metadata attributes on the decorated callable; they do almost nothing at runtime.

### Design principles

- **Parasitic, not parallel.** Standard decorators importable from a PyPI package. No custom syntax, no framework lock-in.
- **Sparse annotation, dense inference.** Annotate boundaries; the scanner infers between. Target: ~50-100 decorators for an 80k-line codebase.
- **Decorators as machine-readable institutional knowledge.** Each decorator converts a prose-level institutional constraint into a machine-checkable declaration.

### Group 1 decorator mapping

| Decorator | Equivalent | Scanner Checks |
|---|---|---|
| `@external_boundary` | Sources TIER_4 | Return tagged EXTERNAL_RAW |
| `@validates_shape` | T4→T3 | Body must contain rejection path (WL-007) |
| `@validates_semantic` | T3→T2 | Body must contain rejection path (WL-007). Inputs must trace to shape-validated output (WL-008) |
| `@validates_external` | T4→T2 combined | Body must contain both structural and semantic checks |
| `@tier1_read` | Sources TIER_1 | Body bans: `.get()` with defaults, `getattr()` with fallbacks, broad `except` |
| `@audit_writer` | T2→T1 + call-site enforcement | Audit must dominate telemetry. Fallback paths produce findings |
| `@authoritative_construction` | T2→T1 | Same body restrictions as `@tier1_read` |

### Body evaluation context

| Decorator | Input tier | Body evaluation severity | PY-WL-003 suppression |
|-----------|-----------|-------------------------|----------------------|
| `@validates_shape` | TIER_4 | EXTERNAL_RAW | Yes — existence-checking is the purpose |
| `@validates_semantic` | TIER_3 | SHAPE_VALIDATED | No — structural guarantees established |
| `@validates_external` | TIER_4 | EXTERNAL_RAW | Yes — encompasses shape validation |

### Contradictory combination detection (SCN-021)

The scanner detects 29 mutually exclusive decorator combinations (26 contradictory, 3 suspicious) as ERROR findings. Key examples: `@fail_open` + `@fail_closed` (mutually exclusive failure modes), `@external_boundary` + `@int_data` (mutually exclusive data sources), `@validates_shape` + `@validates_semantic` (use `@validates_external` for combined T4→T2).

## Type system and runtime enforcement

Python uses three complementary enforcement mechanisms beyond the AST scanner:

| Layer | When It Fires | What It Catches | Coverage |
|-------|--------------|-----------------|----------|
| **AST scanner** | CI time | Pattern violations across entire codebase | Broad. Known false-negative surface. |
| **Type system (Protocols)** | Development time (IDE) | Tier mismatches at function call sites | Narrow — only where mypy/pyright enabled. |
| **Runtime (descriptors)** | Access time | Fabricated defaults on Tier 1 fields | Narrow but absolute within scope. |
| **Runtime (`__init_subclass__`)** | Import time | Unclassified methods on high-assurance base classes | Narrow but absolute within scope. |

**`AuthoritativeField` descriptors** raise on access-before-set, making fabricated defaults structurally impossible for Tier 1 data. **`__init_subclass__` enforcement** requires subclass methods to carry wardline decorators, firing at import time.

## Regime composition matrix

| Capability | Best Home | Profile | Rationale |
|---|---|---|---|
| Syntactic pattern detection (PY-WL-001-005) | ruff rules | Advisory | Pure AST match. Fast, fires at IDE time. No manifest. |
| Tier-aware severity grading (all WL rules) | Reference scanner | Wardline-Core | Requires manifest consumption |
| Taint-flow tracking | Reference scanner | Wardline-Core | No existing tool consumes the manifest's trust topology |
| Context-dependent rules (PY-WL-006-009) | Reference scanner | Wardline-Core | Requires semantic context |
| Type-layer tier-mismatch diagnostics | mypy plugin | Wardline-Type | Extends mypy's type-flow analysis |
| Runtime tier enforcement | Decorator library | Foundation | Python-native OOP machinery |
| Manifest validation, fingerprint baseline, SARIF aggregation, control-law reporting | wardline CLI | Wardline-Governance | Shared across regimes |

**Anti-recommendations:** Do not force tier-aware taint analysis into ruff (per-file architecture). Do not make mypy own governance artefacts. Do not use Semgrep as the normative rule source unless it can faithfully consume the wardline manifest.

## Residual risks (Python-specific)

These supplement the framework-level [residual risks]({{< relref "residual-risks" >}}):

1. **Dynamic dispatch and metaprogramming** — `getattr(obj, method_name)()`, `**kwargs` forwarding, metaclass-generated methods are invisible to the AST scanner.
2. **Taint laundering via serialisation** — Tier 4 data written to a database and read through an `@int_data` function may be classified at a higher tier than its provenance warrants.
3. **Combined false-negative surface** — the two-hop undecorated heuristic and function-level taint approximation compound at the first analysis level.
4. **Decorator selection correctness** — the scanner cannot verify that the decorator choice itself is correct. An agent that applies `@fail_open` where `@fail_closed` is needed produces no structural finding.
5. **Governance decay** — under deadline pressure, every governance gate becomes a candidate for rubber-stamping.
6. **Fingerprint baseline deletion** — deleting `wardline.fingerprint.json` resets the governance history.
7. **Runtime structural enforcement bypass** — `__dict__` manipulation bypasses the descriptor's `__set__` sentinel check.
8. **Third-party library taint accuracy** — Pydantic model defaults in third-party code may escape scanning; two-hop call-graph heuristic may not follow calls into library source.

## Worked example

**Scenario:** A government risk assessment system receives partner data from an external API, validates it, and produces an authoritative risk assessment record.

```
External API response (T4)
    → parse_partner_response() → PartnerDTO (T3)
        → validate_partner_semantics() → ValidatedPartner (T2)
            → create_risk_assessment() → RiskAssessment (T1)
```

**Step 1: External boundary (T4)**

```python
@external_boundary
def fetch_partner_data(partner_id: str) -> dict:
    response = requests.get(f"{PARTNER_API_URL}/{partner_id}")
    response.raise_for_status()
    return response.json()
```

**Step 2: Shape validation (T4 → T3)**

```python
@validates_shape
def parse_partner_response(raw: dict) -> PartnerDTO:
    required = {"partner_id", "name", "country_code", "security_classification"}
    missing = required - raw.keys()
    if missing:
        raise SchemaError(f"Missing fields: {missing}")
    # ... type checking, schema_default() for optional fields ...
    return PartnerDTO(...)
```

**Step 3: Semantic validation (T3 → T2)**

```python
@validates_semantic
def validate_partner_semantics(dto: PartnerDTO) -> ValidatedPartner:
    if dto.country_code not in VALID_COUNTRY_CODES:
        raise DomainValidationError(f"Unrecognised country code: {dto.country_code!r}")
    # ... domain constraint checks ...
    return ValidatedPartner(...)
```

**Step 4: Trusted construction (T2 → T1)**

```python
@authoritative_construction
def create_risk_assessment(partner: ValidatedPartner, context: AuditContext) -> RiskAssessment:
    return RiskAssessment(
        assessment_id=generate_assessment_id(),
        partner_id=partner.partner_id,
        risk_level=compute_risk_level(partner),
        assessed_by=context.identity,
        assessed_at=context.timestamp,
    )
```

## Adoption strategy

| Phase | Components | Coverage |
|-------|-----------|----------|
| **1** | `wardline-decorators`, `wardline-ruff` | IDE-time advisory warnings. No manifest required. |
| **2** | Add `wardline.yaml`, `wardline-scanner` | Tier-aware severity grading, SARIF output. Governance-grade findings begin. |
| **3** | `wardline-mypy` | Development-time tier-mismatch diagnostics. |
| **4** | `AuthoritativeField` descriptors, `__init_subclass__` bases | High-risk paths become structurally impossible to violate. |
| **5** | `wardline-cli` | Fingerprint baseline, exception register management, SARIF aggregation. |

**Annotation budget:** ~50-100 decorators for an 80k-line codebase in the initial pass.

## Error handling and control law

| Scenario | Behaviour |
|----------|----------|
| Syntax error in Python file | Skip; WARNING. Escalate to ERROR if Tier 1 module. |
| Invalid `wardline.yaml` | Exit non-zero. Do not scan. |
| Missing `wardline.yaml` | Exit non-zero. Do not scan. |
| Baseline file missing (deleted) | ERROR, exit non-zero. Do not silently re-establish. |

**Exit codes:** 0 (no ERROR findings), 1 (at least one ERROR), 2 (internal error), 3 (direct law).

**Regime-level control-law transitions:**

| Scenario | Control Law |
|---|---|
| All tools ran successfully | Normal |
| ruff plugin unavailable | Alternate |
| mypy plugin unavailable | Alternate |
| Reference scanner unavailable | Alternate (severe) |
| Manifest validation failed | Direct |
| wardline CLI unavailable | Direct |
