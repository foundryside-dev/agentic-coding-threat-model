## Rule description

Audit-critical writes inside broad exception handlers may fail silently, creating gaps in the legal record. The handler catches the audit failure along with everything else, and execution continues as though the record was written.

## Specification

**Severity matrix row:**

| Audit Trail | Pipeline | Shape Val. | Ext. Raw | Unk. Raw | Unk. Shape V. | Unk. Sem. V. | Mixed Raw |
|---|---|---|---|---|---|---|---|
| E/U | E/U | E/St | E/St | E/St | E/St | E/St | E/St |

WL-005 is UNCONDITIONAL in both AUDIT_TRAIL and PIPELINE — the two highest-authority taint states. In pipeline (Tier 2) contexts, audit-critical writes inside broad handlers destroy diagnostic context for data transformation errors.

## Rationale

WL-005 is UNCONDITIONAL in PIPELINE because pipeline data feeds downstream consumers. Lost audit context for transformation errors is an integrity failure regardless of justification. The audit write records the transformation; the broad handler catches the audit failure alongside processing errors. Because pipeline data feeds downstream consumers, lost audit context for transformation errors is an integrity failure regardless of justification.

In all other contexts (SHAPE_VALIDATED through MIXED_RAW), WL-005 is ERROR/STANDARD — wrong by default but governable. The pattern is still dangerous (an audit write that fails silently is a gap in the legal record regardless of context), but the governance model provides a path for cases where the audit write is not the primary concern.

## Examples

**Agent-generated (violation):**
```python
@audit_writer
def record_decision(decision: dict):
    try:
        audit_log.write(decision)       # Audit write
        telemetry.send(decision)        # Telemetry
        notify_stakeholders(decision)   # Notification
    except Exception:  # WL-005: audit write inside broad handler
        logger.warning("Failed to record decision")
```

**Correct:**
```python
@audit_writer
def record_decision(decision: dict):
    audit_log.write(decision)  # Audit write — must succeed or propagate failure
    try:
        telemetry.send(decision)
        notify_stakeholders(decision)
    except Exception:
        logger.warning("Non-audit operation failed")
```

## Detection approach

Static analysis tools detect audit-critical write operations (calls to functions annotated as audit writers or matching configured audit-write patterns) that occur inside broad exception handler bodies. The detection verifies that the audit write is protected from being caught by the same handler that catches non-audit failures.

## Related rules

WL-005 is the intersection of [WL-003]({{< relref "wl-003" >}}) (broad exception handling) and audit-primacy concerns (annotation group 2). When WL-003 and WL-005 both fire, the code has a broad exception handler that catches audit failures — the combined effect is worse than either rule alone.

WL-005 also relates to [WL-004]({{< relref "wl-004" >}}) (silent catching) — when the broad handler that catches the audit write is also silent, the audit failure is both caught and discarded without any trace.
