## Rule description

Data reaching a declared semantic-validation boundary (e.g., `@validates_semantic` in Python, `@ValidatesSemantic` in Java, or equivalent) whose inputs have not passed through a declared shape-validation boundary is structurally unsound. Applying domain-constraint checks to data whose field presence and type correctness have not been established may crash, produce misleading results, or silently operate on wrong types.

This rule formalises invariant 3 from the transition semantics: shape validation must precede semantic validation.

WL-008 is UNCONDITIONAL across all eight states. Semantic validation applied to structurally unverified data is a category error regardless of context. This is a framework invariant.

## Rationale

WL-008 is an ordering constraint, not a body-content check. The scanner verifies that a declared semantic-validation boundary's inputs trace back to a shape-validation boundary's outputs. A combined validation boundary (e.g., `@validates_external` / `@ValidatesExternal`, T4 to T2) satisfies this requirement internally because it performs both phases. Two separate functions must be ordered: shape validation must precede semantic validation on every data-flow path.

Like WL-007, WL-008 is context-independent — the taint state is irrelevant. Semantic validation applied to structurally unverified data is a category error regardless of context.

## Examples

**Violation — semantic validation on unvalidated data:**
```python
@validates_semantic
def check_partner_domain_constraints(data: dict) -> ValidatedPartner:
    # WL-008: data has not passed shape validation
    if data["amount"] < 0:
        raise ValueError("Amount must be non-negative")
    return ValidatedPartner(**data)
```

**Correct — shape validation precedes semantic validation:**
```python
@validates_shape
def check_partner_structure(data: dict) -> ShapedPartner:
    if "amount" not in data or not isinstance(data["amount"], (int, float)):
        raise ValueError("Missing or invalid amount field")
    return ShapedPartner(**data)

@validates_semantic
def check_partner_domain_constraints(data: ShapedPartner) -> ValidatedPartner:
    if data.amount < 0:
        raise ValueError("Amount must be non-negative")
    return ValidatedPartner(**data.__dict__)
```

**Alternative — combined validation boundary:**
```python
@validates_external  # Combined T4 to T2 — satisfies WL-008 internally
def validate_partner(data: dict) -> ValidatedPartner:
    if "amount" not in data or not isinstance(data["amount"], (int, float)):
        raise ValueError("Missing or invalid amount field")
    if data["amount"] < 0:
        raise ValueError("Amount must be non-negative")
    return ValidatedPartner(**data)
```

## Detection approach

Static analysis tools verify that a declared semantic-validation boundary's inputs trace back to a shape-validation boundary's outputs via data-flow analysis. Combined validation boundaries (T4 to T2) satisfy this requirement internally because they perform both phases. For two separate functions, the scanner verifies that shape validation precedes semantic validation on every data-flow path.

Presentation guidance recommends omitting the taint state from primary finding messages for WL-008, since the rule is context-independent.
