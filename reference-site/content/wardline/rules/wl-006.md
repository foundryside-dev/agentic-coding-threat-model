## Rule description

Internal data's type should be guaranteed by construction. Runtime type-checking (e.g., `isinstance()` in Python, `instanceof` in Java) suggests structural doubt about the system's own artefacts — either the construction guarantee is real (and the check is redundant noise) or it is not (and the check is masking a deeper problem).

In shape-validated contexts (Tier 3), the structural contract has confirmed types, so runtime type-checking is suspicious but less alarming than in authoritative contexts.

## Specification

**Severity matrix row:**

| Audit Trail | Pipeline | Shape Val. | Ext. Raw | Unk. Raw | Unk. Shape V. | Unk. Sem. V. | Mixed Raw |
|---|---|---|---|---|---|---|---|
| E/St | W/R | W/R | Su/T | Su/T | W/R | W/R | W/St |

WL-006 has the widest severity range of any rule — from ERROR in AUDIT_TRAIL to SUPPRESS in EXTERNAL_RAW and UNKNOWN_RAW. It is the only rule with SUPPRESS cells, and the only rule with no UNCONDITIONAL cells.

## Rationale

WL-006 ranges from ERROR/STANDARD in AUDIT_TRAIL contexts to SUPPRESS/TRANSPARENT in EXTERNAL_RAW and UNKNOWN_RAW — type-checking external data at runtime is expected and appropriate, while type-checking the system's own authoritative data suggests structural doubt. SHAPE_VALIDATED and the UNKNOWN validated states occupy the middle ground at WARNING/RELAXED — type correctness has been structurally confirmed, making runtime type-checking suspicious but not as alarming as in authoritative contexts.

- **AUDIT_TRAIL (E/St):** Type-checking the system's own authoritative data is ERROR — it suggests the code does not trust the construction guarantees that define Tier 1. STANDARD exceptionability because there may be legitimate reasons (e.g., defensive coding during migration).
- **PIPELINE (W/R) and SHAPE_VALIDATED (W/R):** The structural contract has confirmed types, so runtime type-checking is partially redundant. WARNING with RELAXED governance.
- **EXTERNAL_RAW (Su/T) and UNKNOWN_RAW (Su/T):** Type-checking is expected and appropriate — we don't know the types yet. SUPPRESS.
- **UNKNOWN_SHAPE_VALIDATED (W/R) and UNKNOWN_SEM_VALIDATED (W/R):** Type correctness has been confirmed by validation, making runtime type-checking suspicious. WARNING with RELAXED governance.
- **MIXED_RAW (W/St):** Mixed-provenance data warrants more scrutiny. WARNING with STANDARD governance.

In statically typed languages, WL-006 may be partially or wholly addressed by the type system itself.

## Examples

**Agent-generated (violation in Tier 1 context):**
```python
@tier1_read
def get_audit_classification(record: AuditRecord) -> str:
    classification = record.classification
    if isinstance(classification, str):  # WL-006: type guaranteed by construction
        return classification
    return "UNKNOWN"
```

**Correct:**
```python
@tier1_read
def get_audit_classification(record: AuditRecord) -> str:
    return record.classification  # Type guaranteed by Tier 1 construction
```

**Legitimate use in Tier 4 context:**
```python
@external_boundary
def parse_partner_field(value: Any) -> str:
    if isinstance(value, str):  # Legitimate — external data type is unknown
        return value
    raise ValueError(f"Expected string, got {type(value)}")
```

## Detection approach

Static analysis tools detect runtime type-checking idioms — `isinstance()`, `type()` comparisons in Python; `instanceof` in Java — applied to tier-classified data. The detection checks the taint state against the severity matrix. In EXTERNAL_RAW and UNKNOWN_RAW contexts, the finding is suppressed. In authoritative contexts, it is elevated to ERROR.
