## Rule description

Using existence-checking as a structural gate substitutes structural probing for proper type identity. In contexts where the wardline declares structural guarantees *and* provenance is known or semantically confirmed — Tier 1, Tier 2, Tier 3, and UNKNOWN_SEM_VALIDATED — existence-checking is unconditionally suspicious because it either masks a defect or is redundant noise.

In UNKNOWN_SHAPE_VALIDATED — where structure has been validated but provenance remains unknown (the common case for third-party library output run through `@validates_shape`) — WL-002 fires as ERROR/STANDARD (governable), reflecting that the unknown provenance introduces residual uncertainty warranting governance discretion rather than absolute prohibition.

In EXTERNAL_RAW, UNKNOWN_RAW, and MIXED_RAW contexts — where structural guarantees have not been established — WL-002 fires as ERROR/STANDARD (governable), reflecting that existence-checking may be legitimate domain logic.

## Specification

**Severity matrix row:**

| Audit Trail | Pipeline | Shape Val. | Ext. Raw | Unk. Raw | Unk. Shape V. | Unk. Sem. V. | Mixed Raw |
|---|---|---|---|---|---|---|---|
| E/U | E/U | E/U | E/St | E/St | E/St | E/U | E/St |

WL-002 has the most UNCONDITIONAL cells (4) of any pattern rule, plus UNCONDITIONAL in UNKNOWN_SEM_VALIDATED. The derivation principle: where the wardline declares structural guarantees *and* provenance is known or semantically confirmed, existence-checking is either redundant or masking a defect; where structural guarantees exist but provenance is unknown, the check is governable; where no guarantee is declared, the check may be legitimate domain logic.

## Rationale

This is the cell that most directly motivates the four-tier split. Shape-validated data has passed structural validation — field presence and type correctness are guaranteed by the T4-to-T3 transition. An `if "field" in record:` check on shape-validated data is unconditionally wrong: the structural contract guarantees the field exists, so the check is either redundant (masking dead code) or indicates that the structural contract is not trusted (masking a deeper problem).

In EXTERNAL_RAW (Tier 4), the same check may be legitimate — the data has not been shape-validated, so field presence is genuinely uncertain. The STANDARD exceptionability accommodates domain logic where existence-checking is the appropriate pattern for raw data.

**UNKNOWN_SHAPE_VALIDATED nuance.** WL-002 is ERROR/STANDARD rather than UNCONDITIONAL in UNKNOWN_SHAPE_VALIDATED: shape validation has established structural guarantees, but the data's provenance remains unknown — the agency validated structure without knowing where the data came from. This is the common case for third-party library output that has been run through an application-side `@validates_shape` boundary. Existence-checking on such data is suspicious (the shape contract guarantees field presence), but the unknown provenance introduces residual uncertainty that makes a governable exception more proportionate than an absolute prohibition. Making this cell UNCONDITIONAL would create a perverse incentive: agencies that invest in validating library output face stricter enforcement than agencies that leave it as UNKNOWN_RAW, discouraging the validation step the framework is designed to encourage.

Architectural guidance: EXTERNAL_RAW (Tier 4) data processing should occur within validation boundaries where existence-checking is expected.

## Examples

**Agent-generated (violation in Tier 3 context):**
```python
@validates_shape
def process_record(record: ValidatedRecord):
    if hasattr(record, "classification"):  # WL-002: structural contract guarantees this
        process_classification(record.classification)
```

**Correct:**
```python
@validates_shape
def process_record(record: ValidatedRecord):
    process_classification(record.classification)  # Structural contract guarantees field exists
```

**Legitimate use in Tier 4 context:**
```python
@external_boundary
def parse_partner_data(raw: dict):
    if "optional_metadata" in raw:  # Legitimate — external data has no structural guarantee
        metadata = raw["optional_metadata"]
```

## Detection approach

Static analysis tools detect existence-checking idioms — `hasattr()`, `in` operator on dictionaries, `Map.containsKey()`, and language-specific equivalents — applied to tier-classified data. The detection checks the taint state against the severity matrix. In contexts with structural guarantees (Tier 1, Tier 2, Tier 3, UNKNOWN_SEM_VALIDATED), the finding is UNCONDITIONAL. In contexts without guarantees (EXTERNAL_RAW, UNKNOWN_RAW, MIXED_RAW) or with partial guarantees (UNKNOWN_SHAPE_VALIDATED), the finding is STANDARD.
