## Rule description

Catching exceptions silently (no action taken) destroys evidence. The exception and its diagnostic context are lost. In any context where failure is meaningful, silent exception handling is a repudiation vector.

## Specification

**Severity matrix row:**

| Audit Trail | Pipeline | Shape Val. | Ext. Raw | Unk. Raw | Unk. Shape V. | Unk. Sem. V. | Mixed Raw |
|---|---|---|---|---|---|---|---|
| E/U | E/St | E/St | E/St | E/St | E/St | E/St | E/St |

WL-004 is ERROR across all taint states. It is UNCONDITIONAL only in AUDIT_TRAIL; in all other states it is STANDARD. Silent exception handling is never appropriate — the distinction between UNCONDITIONAL and STANDARD reflects the severity of evidence destruction, not its acceptability.

## Rationale

Silent exception handling is categorically wrong in almost every context. The AUDIT_TRAIL UNCONDITIONAL designation reflects that silent evidence destruction in authoritative contexts is never acceptable under any governance exception. In all other contexts, WL-004 is ERROR/STANDARD — wrong by default but governable with documented rationale. The governance path exists because there are rare cases where a genuinely empty handler is the correct response, but the burden of proof is on the developer to justify why the exception's diagnostic context can be safely discarded.

## Examples

**Agent-generated (violation):**
```python
@tier1_read
def process_audit_entry(entry_id: str):
    try:
        record = fetch_record(entry_id)
        write_to_audit_log(record)
    except Exception:  # WL-004: silent catch — evidence destroyed
        pass
```

**Correct:**
```python
@tier1_read
def process_audit_entry(entry_id: str):
    record = fetch_record(entry_id)
    write_to_audit_log(record)
    # Exceptions propagate — failure is visible and traceable
```

## Detection approach

Static analysis tools detect exception handlers whose body contains no statements (bare `pass`, empty block) or only contains a comment. The detection checks whether the handler discards the exception without logging, re-raising, or taking any other action that preserves the diagnostic context.

## Related rules

WL-004 is a stricter form of [WL-003]({{< relref "wl-003" >}}) (broad exception catching). WL-003 catches the breadth of the handler; WL-004 catches the emptiness of the handler body. Code that fires both WL-003 and WL-004 has a broad catch that does nothing — the most destructive combination for evidence preservation.

WL-004 also relates to [WL-005]({{< relref "wl-005" >}}) (audit writes in broad handlers) — when an audit write is inside a silent handler, the audit failure is both caught and ignored.

## Related ACF entries

- **[ACF-R1](../../acf/r1-audit-trail-destruction/)** (Audit Trail Destruction) — silent exception handling is the most direct mechanism for audit trail destruction. The exception is caught, its diagnostic context is discarded, and execution continues with no record that a failure occurred.
